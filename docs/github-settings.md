# Repository presentation settings

## Description and topics

Configured searchable description:

> Evidence-driven reverse engineering for source code, binaries and software architecture. Offline CLI with a provider-backed MCP engine.

Relevant topics: `reverse-engineering`, `static-analysis`, `binary-analysis`, `source-analysis`, `software-architecture`, `dependency-analysis`, `call-graph`, `ghidra`, `mcp`, `cli`, `developer-tools`, `provenance`, `elf`, `pe`, `macho`, `javascript`, `typescript`.

These describe the repository's scope; they do not certify experimental providers or compiler-level accuracy. No traffic/stars automation or promotional posting is used.

## Manual settings after review

1. Review and merge the documentation PR when appropriate. It is not merged automatically; draft PR #1 stays separate.
2. In repository **Settings → General → Social preview**, upload [social-preview.png](../assets/brand/social-preview.png), 1280×640. [GitHub's official guide](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview) explains the setting. No website URL is invented or deployed.
3. Optionally pin useful existing guides/issues and enable Discussions if the maintainer wants a community space. Do not advertise an inactive Discussions page.
4. Adapt [the launch draft](launch-announcement.md) to a relevant community's rules, verify branch status again and post manually only if appropriate.

Do not enable npm/registry publication, Pages, releases or deployment workflows as part of repository presentation.
